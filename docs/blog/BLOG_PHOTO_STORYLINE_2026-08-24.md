# 최종 블로그 사진 스토리라인 점검

## 점검 결론

기존 배치의 가장 큰 문제는 본문은 `문제 → 수정 이유 → 개선 결과`를 설명하지만, 사진은 대부분 완성 화면 한 장만 보여준다는 점이었습니다. 독자는 화면이 좋아졌다는 결과는 볼 수 있어도 무엇이 왜 달라졌는지는 사진만으로 확인하기 어려웠습니다.

다음 기준으로 사진 흐름을 보정했습니다.

1. 변화 과정을 설명하는 문단에는 같은 기능의 `BEFORE → AFTER` 비교 이미지를 둡니다.
2. 사용자 흐름을 설명하는 문단에는 화면 캡처 대신 전체 여정 도식을 둡니다.
3. AI 공동설계처럼 화면만으로 동작을 설명하기 어려운 부분은 실제 화면과 작동 로직 도식을 연속 배치합니다.
4. 강의 후기와 QA 문단에는 서비스 화면이 아니라 적용 원칙과 버전 변화 도식을 둡니다.

## 본문과 잘 맞지 않아 단독 배치에서 제외한 사진

- `02-home-dashboard.png`: 완성 화면만 보여줘 ‘왜 수정했는지’가 약하므로 홈 전후 비교판 안에서 사용합니다.
- `03-professor-pitch.png`: 결과 화면만 보면 기존 교수 허브와의 차이가 드러나지 않아 교수 전후 비교판 안에서 사용합니다.
- `04-meeting-prep.png`: 도구가 어떻게 더 잘 보이게 됐는지 비교가 필요해 만남 준비 전후 비교판 안에서 사용합니다.
- `08-growth-journey.png`: ‘성장 기록을 새로 만들었다’는 문장만 보조하므로 기존 빈 화면과 함께 비교합니다.
- `12-service-screen-map.png`, `13-two-matching-contexts.png`, `15-trust-evidence-model.png`: 내용은 좋지만 최종 글에 모두 넣으면 도식이 연속되어 호흡이 느려집니다. 발표자료나 후속 글에 사용하는 편이 좋습니다.

## 네이버 블로그에 넣을 때

- 전후 비교 이미지는 본문 폭을 넓게 사용하고, 사진 설명은 이미지 아래 한 줄만 둡니다.
- 전후 비교 이미지 사이에 다른 사진을 끼우지 않습니다. 한 장 자체가 문제와 결과를 함께 설명합니다.
- AI 공동설계의 두 이미지는 `실제 화면 → 작동 로직` 순서로 연속 배치합니다.
- 이미지 앞 문단 마지막 문장이 이미지의 질문이 되고, 캡션이 그 질문의 답이 되게 유지합니다.
