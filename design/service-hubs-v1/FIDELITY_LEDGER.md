# Fidelity ledger

검수 크기: 데스크톱 1440×900, 모바일 390×844

| 비교 지점 | 시안 | 실제 렌더 | 판단·조치 |
| --- | --- | --- | --- |
| 첫 화면 위계 | 큰 제목, 한 줄 설명, 한 개의 주 행동 | 세 허브 모두 같은 순서와 크기 관계 | 일치 |
| 컨테이너 모델 | 주 행동만 라벤더 면, 나머지는 열린 행 | 카드 그리드 없이 주 행동 1개와 구분선 행 사용 | 일치 |
| 교수 허브 정보량 | 교수 연결 2행과 보조 이동 | 저장 상태의 선택 교수·저장 교수 2행, 직접 입력·관리 행 | 저장 상태를 보여주기 위한 의도된 상태 변형 |
| 대화 준비 모바일 | 주 행동과 만나기 전·중·후, 고정 하단 메뉴 | 390×844에서 주 행동과 3단계, 하단 메뉴가 한 뷰에 보임 | 시안보다 패널 높이를 줄여 작은 실제 브라우저에 맞춤 |
| 성장 기록 구조 | 완료 2행, 다음 빈 단계 1행, 만들기·관리 | 실제 저장 상태에 따라 같은 3행과 두 전용 이동 표시 | 일치 |
| 색·타이포 | 흰 배경, 딥 네이비, 바이올렛, 민트 | `#FFF`, `#0B1733`, `#6547E8`, `#087F68` 토큰 적용 | 일치 |
| 아이콘 | 2px 안팎의 단순 선형 아이콘 | Lucide 계열을 같은 크기·색·원형 면 규칙으로 통일 | 일치 |
| 반응형 내비게이션 | 데스크톱 좌측, 모바일 하단 | 1024px 기준으로 서로 전환, 모바일는 fixed와 safe-area 적용 | 일치 |
| 콘텐츠 상태 | 시안은 예시 빈 상태·첫 질문 상태 | 렌더는 브라우저에 저장된 교수·논문·진행 상태 | 실제 데이터 계약을 지키기 위한 의도된 차이 |

로딩 상태 복원 전에 찍힌 초기 QA 캡처 두 장은 사용하지 않고, 실제 콘텐츠가 복원된 뒤 다시 캡처했다. 최종 렌더에서 잘림·가로 넘침·고정 하단 메뉴 충돌·콘솔 오류는 발견되지 않았다.
