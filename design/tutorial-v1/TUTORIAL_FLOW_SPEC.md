# 첫 매칭 튜토리얼 v1 흐름 명세

작성일: 2026-08-20
대상: 랜딩페이지에서 처음 유입된 단국대학교 학생

## 1. 목적

처음 온 학생이 메뉴를 탐색하지 않아도 자신의 고민을 한 번에 한 질문씩 정리하고, 학교 공식 정보에 근거한 첫 교수 연결까지 완료하게 한다.

이 튜토리얼은 단순한 기능 안내가 아니다. 기존 `/professors`의 2단계 입력과 공식 교수 매칭을 처음 방문자에게 맞게 재구성한 실제 진입 흐름이다.

## 2. 성공 기준

- 첫 화면에서 `무엇을, 얼마나, 왜 입력하는지` 이해할 수 있다.
- 기본 질문만 답해도 첫 매칭을 시작할 수 있다.
- 심층 입력은 교수 근거를 바꾸는 정보가 아니라 첫 질문을 구체화하는 정보임을 명시한다.
- 뒤로 가기, 새로고침, API 오류 뒤에도 입력을 잃지 않는다.
- 결과는 점수나 순위 없이 세 관점과 공식 출처로 설명한다.
- 교수에게 자동 연락하지 않으며 최종 연락과 선택은 학생이 직접 한다.

## 3. 화면 지도

```mermaid
flowchart TD
  A[랜딩페이지 CTA] --> B[시작 안내]
  B --> C[학교와 전공]
  C --> D[현재 단계]
  D --> E[원하는 도움]
  E --> F[관심 분야]
  F --> G[현재 고민]
  G --> H{입력 깊이 선택}
  H -- 기본으로 보기 --> M[공식 교수 매칭]
  H -- 2분 더 알려주기 --> I[관심 직무와 진로 목표]
  I --> J[원하는 도움 방식과 만남 상황]
  J --> K[궁금한 주제와 경험]
  K --> L[최종 확인]
  L --> M
  M --> N[/professors/pitch]
  M -- 오류 --> O[입력 유지 + 다시 시도]
  O --> M
```

## 4. 단계별 책임

| 단계 | 학생이 하는 일 | 서비스가 하는 일 | 필수 여부 |
| --- | --- | --- | --- |
| 시작 안내 | 예상 시간과 결과 확인 | 질문 방식·정보 원칙 안내 | 필수 |
| 학교·전공 | 단과대와 전공 선택 | 단국대 공식 분류 제공 | 필수 |
| 현재 단계 | 지금의 상태 선택 | 첫 질문 맥락으로 저장 | 필수 |
| 원하는 도움 | 이번 대화의 목적 선택 | 행동 목적을 명확히 함 | 필수 |
| 관심 분야 | 관심 분야 1~5개 선택 | 공식 교수 분야 대조 입력으로 사용 | 필수 |
| 현재 고민 | 진로 고민 1~2개 선택 | 면담 질문 개인화에 사용 | 필수 |
| 입력 깊이 선택 | 바로 보기 또는 심층 입력 선택 | 기본 입력만으로도 매칭 허용 | 필수 |
| 심층 입력 | 직무·목표·상황·경험 입력 | 첫 질문을 더 구체화 | 선택 |
| 최종 확인 | 입력 요약 확인 | 공식 교수 매칭 요청 준비 | 선택 경로에서 필수 |
| 매칭 중 | 기다리거나 오류 재시도 | 입력 정리 → 공식 근거 대조 → 첫 매칭 구성 | 필수 |

## 5. 데이터 계약

튜토리얼은 `ProfessorDiscoveryContext`를 단일 정답 데이터로 사용한다.

- 공식 근거 대조에 사용하는 항목: 학교, 단과대, 전공, 관심 분야, 사용자가 직접 적은 궁금한 주제
- 질문 개인화에 사용하는 항목: 현재 단계, 원하는 도움, 진로 고민, 관심 직무, 진로 목표, 만남 상황, 도움 방식, 경험, 추가 맥락
- 금지: 진로 고민이나 만남 상황을 교수의 공식 연구 근거로 표현
- 금지: 궁합 점수, 교수 순위, 합격 가능성, 지도 가능성 추정

서버 경계는 기존 `requestProfessorDiscoveryMatches()`를 재사용한다. 성공 응답은 기존 Zustand 저장소의 교수 매칭 결과·탐색 주제·탐색 요약에 저장하고 `/professors/pitch`로 이동한다.

## 6. 임시저장과 복구

- 브라우저 로컬 저장 키: `major-evolution-professor-tutorial-v1`
- 저장 내용: 현재 단계, 기본/심층 선택, `ProfessorDiscoveryContext`
- 새로고침 시 저장된 단계와 입력을 복원한다.
- 매칭 성공 직전에 임시저장을 삭제한다.
- 저장값 구조가 잘못되었거나 버전이 다르면 안전하게 초기화한다.

## 7. 예외 흐름

| 예외 | 처리 |
| --- | --- |
| 단과대 변경 | 이전 전공 선택을 비우고 새 단과대 전공만 노출 |
| 필수 선택 누락 | 해당 화면 안에서 다음 버튼을 비활성화하고 선택 기준 표시 |
| 최대 선택 초과 | 기존 선택을 유지하고 최대 개수 안내 |
| 새로고침 | 현재 입력과 단계 복원 |
| 매칭 API 실패 | 입력을 유지하고 같은 화면에서 다시 시도 제공 |
| 뒤로 가기 | 직전 질문으로 이동, 값 유지 |
| 심층 입력 건너뛰기 | 기본 입력으로 바로 매칭 |

## 8. 반응형 원칙

- PC: 왼쪽 진행 맥락, 오른쪽 질문 카드의 2열 구조
- 모바일: 진행 요약 → 질문 → 하단 행동 버튼의 1열 구조
- 선택지는 키보드와 터치 모두 사용할 수 있는 실제 버튼으로 구현
- 진행률은 완료한 질문 수를 기준으로 표시하고 성공 가능성처럼 보이는 수치는 사용하지 않음
