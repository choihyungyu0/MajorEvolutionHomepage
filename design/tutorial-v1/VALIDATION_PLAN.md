# 첫 매칭 튜토리얼 v1 검증 계획

작성일: 2026-08-20

## 검증 원칙

첫 매칭까지 이어지는 세 가지 위험 흐름을 우선 검증한다. 내부 데모 성공을 사용자 효과 검증으로 표현하지 않는다.

## 시나리오 1 — 첫 방문자 기본 경로

- 시작: 랜딩페이지의 `3분 방향 찾기`
- 행동: 전공 → 현재 단계 → 원하는 도움 → 관심 분야 → 고민 선택 → `이 정보로 첫 매칭 보기`
- 성공 기준:
  - 처음부터 다음 할 일이 한 가지로 보인다.
  - 모든 필수 답이 실제 교수 매칭 요청에 포함된다.
  - `/professors/pitch`에서 세 관점의 교수 카드와 연결 이유를 확인한다.
  - 점수·순위 표현이 없다.
- 실패 기준:
  - 기존 복잡한 교수 찾기 폼으로 갑자기 이동한다.
  - 필수 입력 없이 진행하거나 선택값이 결과 요청에서 사라진다.

## 시나리오 2 — 심층 입력 경로

- 시작: 기본 질문 완료 화면
- 행동: `2분 더 알려주기` → 관심 직무·진로 목표 → 도움 방식·만남 상황 → 주제·경험 → 최종 확인 → 매칭
- 성공 기준:
  - 심층 입력의 목적이 `교수 근거 강화`가 아니라 `첫 질문 구체화`로 설명된다.
  - 결과 카드의 확인 질문에 심층 맥락이 반영된다.
  - 공식 근거 영역에는 진로 고민·만남 상황이 섞이지 않는다.
- 실패 기준:
  - 심층 입력을 하지 않으면 매칭할 수 없다.
  - 개인 맥락이 교수의 공식 전문성 사실처럼 표시된다.

## 시나리오 3 — 중단과 오류 복구

- 시작: 튜토리얼 중간 또는 매칭 요청 직전
- 행동: 새로고침 → 이전 답과 단계 확인 → 매칭 요청 실패 상황 → 다시 시도
- 성공 기준:
  - 새로고침 뒤 입력과 단계가 복원된다.
  - 오류 뒤에도 입력이 유지된다.
  - 다시 시도가 중복 결과나 오래된 응답으로 화면을 덮지 않는다.
- 실패 기준:
  - 입력이 초기화된다.
  - 오류 원인이나 다음 행동이 보이지 않는다.
